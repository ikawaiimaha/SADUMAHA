# Confirmed handoffs: prototype implementation

## Communication to collection

In `/overview#experience`, assign and accept the backup, then choose **Resolve an incoming date discrepancy**. A prepared source says 3 December, outside the fixed October window. Check the synthetic transcript against prepared text, link DEMO-001, open a clarification task, record a separate response/date, explicitly confirm it, then apply it to the existing collection state. The source, reply, recorder and transition history remain available. Applying the date continues into the packing gate; it cannot book freight.

No audio, inbox or communication API is connected. Real audio verification is not claimed. Dates outside the window remain blocked instead of being silently corrected. Failed transitions preserve form contents and do not advance the local task.

## Curatorial handoff

`/overview#curatorial-handoff` provides proposal → completeness/findings → optional specialist review → comparative Committee recommendation → separate Director approval → unsent invitation preview. Two synthetic candidate descriptions share the sample brief. Named simulated owners and revision guards enforce the order. Returns require a reason. Amendments increment the proposal revision, clear current downstream review/decision fields and preserve the earlier history and submitted content.

The authority route is an explicit rehearsal assumption, not verified institutional delegation. This separate model does not redefine or mutate ArtistStatus or ThemeStatus. It does not implement real Committee voting, authentication, live invitations or executed contracts.

## Boundaries

Both are browser-session demonstrations, resettable and cleared by refresh. Source and decision data are synthetic. Existing shared task/evidence cards, accepted backup, packing checks and separate ready/booked/collected labels are retained. Production authorization, persistent multi-user transactions, original-audio storage and external ingestion remain unconnected. Do not present these local guards as backend security.
